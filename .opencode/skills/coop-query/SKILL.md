# 查询游戏数据

回答用户所问的事实，不调用 plan_prepare、plan_submit 或其他写入工具。工具用法按需读共用的 [查询速查](search.md)。

## 查什么

- 复用系统名册、面板技能表或会话中已确认的对象。缺少身份才解析名称；缺少工程上下文才读 project_status。
- 沿相关 objectCard 条目定位所问字段。问官方基础值可使用基线证据；问当前工程值则精确读取 path。已有所需证据时跳过浏览，独立字段可批量读取。
- 只核对影响本题答案的条件。用户指定威望、等级或组合时采用该条件；普通属性问题说明当前采用的基础或工程口径，不主动枚举全部威望、精通和研究。

## 什么时候继续

继续查询应能解决一个影响答案的具体问题，例如两个可能控制同一效果的字段给出不同值、返回了相关修正，或已知脚本会覆盖该字段。沿执行关系、条件或对应源码定向查证，疑点解决后回到原问题。

同名对象、解锁列表和关联入口只提供线索，不表示它们都控制所问数值。只有 `unknown`、`complete=false`、空影响列表或未识别消费者时，保留证据边界即可，不为证明“没有其他影响”遍历全图。需要的字段尚未返回时才继续分页；工具可编辑性不决定一个只读事实能否回答。

## 什么时候回答

对象、字段含义、所问数值及会改变结论的已知条件已明确，就回答。若关键疑点仍未解决，交付已知部分和具体缺口；用户问实际效果时，不能把基础字段值包装成实际结果，也不能把未回答的部分记为完成。

task_checkpoint.summary 先给答案，必要时补一句适用条件或不确定性。完整回答记 complete；只回答部分记 partial；核心问题无法回答记 unresolved。普通查询无需附带修改验收清单，也无需游戏实测才能陈述静态数据事实。
