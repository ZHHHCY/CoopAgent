# Scalar 参数接口实验

本次修正的契约：查询已确定的字段地址、当前值和依赖应由程序传递给执行层，普通数值修改不应要求模型重新编写这些信息及 PatchPlan 外壳。

## 已实现的链路

```text
名称解析 / 对象参数导航
  → 精确字段查询返回 parameterId、当前值与条件
  → scalar_change(parameterId + transform)
  → 后台计算、生成内部 PatchPlan、校验并原子提交
  → 实际应用结果 + 逐字段旧值/新值
  → task_checkpoint 记录本轮交付
```

`parameters` 是可选 Agent 配置。默认 `workflow` 不变。实验配置只暴露 project_status、search、search_batch、scalar_change、target_confirm、task_checkpoint；不注册 scalar_solve、plan_prepare、plan_submit 或旧 change，不开放 shell、文件写入和旧流程 Skill。

精确查询仍使用现有 search/search_batch，并保留用途、字段含义和相关影响证据。模型视图去掉 editState、authoringRoute、requiredDependsOn；原始证据保存在任务侧。对象卡负责定位，卡片预览不冒充当前工程值。只有精确读取且指定 commanderId 的数字字段才可能获得参数标识。

调用示意（parameterId 必须来自实际查询）：

```json
{
  "summary": "将所选单位基础生命改为150",
  "changes": [
    {"parameterId": "查询返回的标识", "transform": {"kind": "set", "value": 150}}
  ]
}
```

支持 set、add、subtract、multiply、divide、increase-percent、decrease-percent。默认使用字段原始数值；只有确实需要百分数/小数或人口符号换算时，显式选择既有 meaning。四舍五入仍须明确 roundingDecimals，不隐式舍入。

## 自动处理与保留边界

- 参数绑定当前服务实例、指挥官、字段、已选条件、当前字段状态、数据库元信息及相关用途/影响证据。服务重启或相关状态变化后重读，不能手工制造参数标识。
- 后台复用 scalar_solve，自动合并依赖、生成计划 ID/兼容性/操作 ID 和摘要，使用现有执行器。相同请求重试复用同一 preparation，不重新累加相对修改；丢失响应可通过返回的 preparationId 恢复。
- `no_change` 只表示本次读取已经满足目标，不缓存为永久交付。再次调用重新核对字段；字段变化后旧参数必须重新读取。已提交请求仍通过 preparation 保持幂等，不受此项调整影响。
- 一次最多 32 项、一个指挥官。任意项目无法读取、过期或不支持时整批不提交，不静默丢项。已达到目标的字段跳过，但不阻止其他字段交付。
- 已有 commander.stat.set 候选使用玩家作用域。直接 Catalog 数字修改必须通过现有 reviewer 的明确私有范围证据；仅“未证明私有”的警告不能自动当成许可。没有自动克隆、全局写入或脚本编辑回退。
- 参数指向可编辑字段，不代表完整条件下的最终战斗数值。首版对威望只开放精确的已有 Upgrade 操作数；带威望条件的普通目标字段不提供参数标识。此限制是实验范围，不代表旧能力不存在。
- 已识别的 script-output 字段不提供可修改参数；unknown 不自动拒绝，也不表示没有消费者。此检查依赖已有用途证据，不新增完整运行时模拟。
- 基础值与威望是否联动、伤害目标含义、最大/出生生命是否一起修改等玩法选择仍由 Agent 根据用户请求决定。后台不猜测这些选择。
- 执行器、请求绑定、原子提交和 Receipt 契约保留。没有调整 harness 时间/步数预算。新入口接入原有提交等待和宿主应用状态通知；组合调用的后台等待包含其准备过程，比较时同时报告总耗时与工具耗时。

本次没有去掉预检/提交的重复执行和临时构建；实验先回答“模型不写计划能否降低交付负担”。后台性能优化另看测量结果。

## 启用与回退

生成配置：

```powershell
node scripts/agent-profile.mjs --profile parameters --output .codex-tmp/opencode-parameters.json
```

该命令生成配置文件，不自动修改应用默认配置。实验运行器会把同一配置构造函数的结果写入隔离工程的 opencode.json。需本地单独试用时，可将生成文件作为 OpenCode 配置使用；恢复原 workflow 配置即回退。不要仅改 MCP 环境变量而保留旧 Agent 提示与权限，否则会混用两套流程。

## 验证

自动测试覆盖数字转换、不同 Catalog、多字段提交、过期/伪造/重复参数、跨指挥官拒绝、连续编辑依赖、no-change 与其他修改共存、提交响应丢失后的幂等恢复、script-output 负例，以及私有范围证据不足的反例。

真实 MCP 预检使用独立工程，确认工具列表已替换，普通字段修改实际写入并产生 Receipt，运行时输出字段不提供参数。没有启动游戏。

六条真实模型对照由以下脚本执行，默认仅输出清单，`--run` 才调用已配置模型：

```powershell
node scripts/scalar-parameter-regression.mjs
node scripts/scalar-parameter-regression.mjs --run --label 2026-09-19-scalar-parameters-v1
```

| 样本 | 目的 |
| --- | --- |
| 蒙斯克劫掠者基础及出生生命设为 500 | 普通数值写入 |
| 阿塔尼斯龙骑士生命 300、护盾 200，均含出生值 | 多字段交付 |
| 雷诺陆战队基础伤害提高 50% | 比例计算及共享对象隔离 |
| 雷诺休伯利安大和炮基础冷却缩短 50% | 技能参数导航及写入 |
| 接着把蒙斯克劫掠者生命各增加 50 | 同会话连续编辑 |
| 虚空碎片死亡之握比例 75% 改为 50% | 不支持公式修改的负例 |

生命和冷却请求复用既有回归输入；其余为固定的同结构变体与跟进输入。完整原文、观察者目标和保持不变项在运行器中。观察者脚本不会复制进模型工程；模型只收到中文请求，不提供 ID、字段地址或预设答案。每组使用相同初始核心和数据库，连续编辑复用各自上一轮工程与任务。负例安全报告不能计作成功修改公式。

每个配置各一次，共 12 次观察；这只能发现明显回归并提供初步成本比较，不足以证明稳定性能提升。报告分别记录实际目标值、保持不变项、应用状态、调用数、token、准备前耗时与准备/提交耗时。未知 token 必须保留为未知。静态写入通过不等于游戏验证。

2026-09-19 的一次对照中，5 个修改样本两边均通过；运行时输出负例两边都未定位到实际 DamageDummy，工程均未修改，机制识别验收未通过。新入口的正例合计 token 下降约 40%，耗时下降约 14%，但冷却样本更慢，不能据此替换默认配置。

真实 MCP 直接查询已确认：一旦读到那个真实输出字段，新接口不会发放可修改参数；这与真实模型能否找到它是两项不同的能力。本轮不补对象专用导航。

首批负例观察者误把“可编辑”当作只读验收前提，尚未调用模型就失败。补跑只修观察者，生产代码、数据库及初始核心指纹保持一致。汇总工具次数时包含失败调用；交付采用已封存的 task.delivery.saved 记录，不把宿主保存的开场进度当作最终答案。原始失败记录保留。

冻结对照结束后，仅补了参数重查时保留精确查询 limit 的修复，防止证据分页不同造成错误的 stale 诊断；新增专项自动测试通过。模型对照的来源指纹仍保留为实际测试版本，不将这项后续修复伪称为已跑过完整模型批次。最终自动回归 178 项通过，Rust 测试后端构建通过。

## 本次职责与复杂度变化

后续稳定性修复与当前维护命令见 [Scalar 产品范围与维护基线](scalar-only.md)。上述模型对照记录仍对应原受测版本；后续自动回归不冒充重新执行该批真实模型。

修改位于 MCP 的模型接口层及配置层；不改游戏数据解析语义、不新增执行器操作。旧工作流保留作对照，但在实验配置下被替换，不要求模型同时学习新旧协议。新增复杂度主要是有状态参数标识与恢复处理；没有按指挥官或具体对象增加生产特判。
